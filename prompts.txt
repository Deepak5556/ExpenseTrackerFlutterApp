Decisions I made for you
Each of these is a deliberate change or addition to your master prompt. Edit the prompts if you disagree.
• SF Pro is replaced by Inter. Apple’s licence limits SF Pro to Apple-platform apps and mock-ups, so shipping it inside an Android app on Google Play isn’t allowed. Inter is the standard free look-alike, and the font is a one-line swap in the prompts. Check Apple’s font licence yourself if you plan a different arrangement.
• A time column is added to Transactions. Your Add Expense form and the Journal table both need a time, but the master column list had none.
• Models move from Phase 5 to Phase 4, because the repositories need them.
• Budget goal added. The mobile reference has a Budget card, so Settings gets a monthlyBudget value. Delete the budget lines in Phases 8 and 9 if you don’t want it.
• Salary rule defined. Salary counts once per month from the setup month onward, and an income entry in the Salary category replaces it for that month, so nothing is counted twice. It is written into Prompt 0A and unit-tested in Phase 6.
• Packages aren’t pinned. ChatGPT must resolve versions with flutter pub add and read current docs. Google Sign-In’s API was rebuilt in v7 (initialize, authenticate, separate authorization), so most older tutorials are wrong, and extension_google_sign_in_as_googleapis_auth v3 is the release that works with it. go_router is the only package added to your list (for app_router.dart).
• Light theme only in v1, built so dark mode can be added later.

4. GOOGLE SHEET SCHEMA (schemaVersion = 1). File name: Expense_Tracker_Data, tagged with Drive appProperties so the app can rediscover it.
Worksheet Transactions (row 1 = headers): transactionId | createdAt | date | time | monthKey | title | amount | category | type | paymentMethod | notes | updatedAt

5. FINANCIAL RULES (implement exactly, unit-test every one)
- Filter by transaction date / monthKey, never by the day the app is opened.
- totalExpenses(M) = sum of Expense transactions in month M.
- baseIncome(M) = monthlySalary for every month from setupMonth through the current month, 0 outside that range. If Income transactions with category Salary exist in M, their sum replaces monthlySalary for M (no double counting).
- totalIncome(M) = baseIncome(M) + sum of the other Income transactions in M.
- remaining(M) = totalIncome(M) − totalExpenses(M). savingsRate = totalIncome > 0 ? remaining / totalIncome × 100 : 0.
- Handle zero income, negative balance and empty lists without errors. Year and all-time views sum the months from setupMonth to the current month.
- Do money arithmetic in integer minor units (paise) or equivalent exact rounding, never raw double sums. Format with intl, INR by default (Indian grouping, ₹1,00,000); currency selectable later.
- Sanity sample: salary 17,000; November expenses Food 274 + Tea/Coffee 112 + Fruits 60 = 446; remaining 16,554; savings rate 97.38%; expense share 2.6%; category ratios 61%, 25%, 13%.
